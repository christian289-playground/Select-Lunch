# Select-Lunch

점심 고르자. 슬랙 채널에서 점심 투표를 열고, 알고리즘으로 식당을 추천하는 봇.

## 하루 흐름

    10:55  오늘의 메뉴 수집 시작 — 투표 개시 5분 전부터 카카오 채널을 확인한다
    11:00  투표 개시 — 등록된 식당 전체가 후보
    11:25  미참여자 알림 — 아직 투표·기권하지 않은 사람에게 본인만 보이는 메시지 1회
    11:30  마감 → 투표 1위 + 알고리즘 추천 (선정 근거 포함)
    13:30  기록 요청 — 실제로 먹은 곳을 남기면 다음 추천이 정확해진다

시각은 모두 설정으로 바꿀 수 있고, **앱 재기동 없이 반영**된다(단, 토큰·채널 ID는
예외 — [알아둘 점](#알아둘-점) 참고). 메뉴 수집 시작 시각은 따로 설정하지 않고
`Lunch:VoteOpenAt`에서 `Lunch:MenuCollectionLeadMinutes`(기본 5분)를 뺀 값으로
계산되므로, 투표 시각을 옮기면 수집 시각도 함께 따라온다.

오늘의 메뉴 사진이 있으면 투표 메시지 **본문이 아니라 그 메시지의 스레드에 파일로**
올라간다. 본문에 외부 이미지 URL을 실으면 슬랙이 그 URL을 직접 가져오다 실패해
메시지 전체를 거절하는 일이 있어(`invalid_blocks`), 봇이 사진을 직접 내려받아
업로드한다. 사진을 못 구해도 투표는 그대로 진행된다.
업로드 완료 기록은 메뉴 날짜별로 관리한다. 새 날짜의 메뉴를 수집하면 이전 완료 기록을
초기화하므로 다음 날에도 올라가고, 같은 날 성공한 메뉴는 중복 게시하지 않는다.

투표 마감 5분 전부터, 아직 투표하거나 기권하지 않은 채널 구성원에게 **본인만 보이는
비공개 메시지**로 투표를 독려한다. 투표 메시지로 이동하는 링크를 포함하며 봇·비활성
계정은 제외한다. 전송 전에 DB에 시도 기록을 남겨 **투표마다 최대 한 번만** 시도하고,
전송 오류나 재시작 뒤에도 다시 보내지 않는다. 마감 시각부터는 보내지 않는다.

투표 메시지에는 후보 버튼과 함께
**"나 오늘 따로 먹어요"** 버튼이 있다. 이건 투표가 아니라 기권 표시로, 집계·동점
해소·추천 점수·식사 기록 어디에도 영향을 주지 않는다 — 누가 따로 먹는지 채널에
보이게 하는 것이 유일한 목적이다. 집계 아래에 `따로 먹어요 (N) — @이름 @이름` 형태로
명단이 뜬다.

후보가 10곳을 넘으면 버튼 대신 드롭다운으로 바뀐다. 이 드롭다운은 **식당 이름뿐 아니라
카테고리(음식 종류)와 주소에도 부분 일치**로 검색된다 — `순대국`만 쳐도
`옛날경성순대국 광교중앙역점`이 나온다. 슬랙 기본 드롭다운은 클라이언트가 단어 앞부분만
맞춰서 `옛날`부터 쳐야 했는데, 검색을 봇이 직접 처리하도록 바꾼 결과다(식사 기록
드롭다운도 같다). 몇 곳이 등록돼 있든 드롭다운이 뜨며, 한 번에 보여주는 건 상위 100곳이다.

식사 기록 메시지와 등록 창에는 **실제 식사 날짜**가 표시된다. 채팅에서 기록할 수 있는
날짜는 설정 타임존 기준 오늘뿐이다. 지난 날짜의 버튼·드롭다운·등록 창을 사용하면
본인에게만 안내하거나 창에 오류를 표시하며, 과거 식사 기록이나 식당 정보는 바꾸지 않는다.
오늘 기록은 다시 선택해 정정할 수 있지만, 과거 기록 복구는 운영자가 백업·원래 확정
메시지를 확인한 뒤 엔티티를 통해 별도로 처리한다.

카테고리 정보가 비어 추천에서 빠진("Pending") 식당이 있으면 매주 금요일
`Lunch:PendingReminder:At`(기본 16:00)에 보완 요청 메시지가 따로 올라온다.

## 추천 알고리즘

랜덤을 쓰지 않는다. 카테고리별로 점수를 매겨 결정적으로 고른다.

    score = D − (W7 × N7 + W30 × N30)

      D   = 마지막으로 먹은 날로부터 경과일 (상한 30, 미방문도 30)
      N7  = 최근 7일 식사 횟수     (기본 가중치 3)
      N30 = 최근 30일 식사 횟수    (기본 가중치 1)

점수가 가장 높은 카테고리에서, 마지막 방문이 가장 오래된 식당을 고른다.
결과만이 아니라 **계산 과정 전체를 메시지에 노출**한다. 기권은 이 계산에 전혀
관여하지 않는다 — 투표하지 않은 것과 동일하게 취급된다.

## 시작하기

1. [Slack 앱 설정](docs/slack-app-setup.md)을 따라 토큰을 발급한다
2. `src/SelectLunch.Slack/appsettings.Local.example.json`을
   `appsettings.Local.json`으로 복사하고 토큰·채널 ID를 채운다
3. 실행한다

```bash
dotnet run --project src/SelectLunch.Slack
```

DB(`data/lunch.db`)는 기동 시 자동 생성·마이그레이션된다. 별도 준비가 필요 없다.
토큰이 비어 있거나 형식이 틀리면(예: `xoxb-`로 시작하지 않음), 또는 `Lunch:TimeZone`이
잘못된 타임존 ID면 스택 트레이스 없이 한 줄 메시지와 함께 즉시 종료한다(종료 코드 1).

## 명령어

`/lunch <서브커맨드>` 형태로 쓴다. 인자 없이 `/lunch`만 치면 도움말이 뜬다.

| 명령 | 동작 |
|---|---|
| `/lunch add [이름]` | 식당 등록 (모달이 열린다) |
| `/lunch list` | 등록된 식당 목록 |
| `/lunch edit [이름]` | 식당 수정 (이름을 넣으면 기존 정보를 채워 연다) |
| `/lunch pending` | 카테고리가 비어 추천에서 빠진 식당 |
| `/lunch stats` | 카테고리별 현재 추천 점수 |
| `/lunch today` | 오늘 투표 상태 다시 보기 |
| `/lunch test` | 투표 메시지를 나에게만 미리 보기(테스트 모드). 누구나 쓸 수 있고 눌러도 집계에 반영되지 않는다 |
| `/lunch help` (또는 그 외 인자) | 위 목록을 요약한 도움말 |

## 식당별 출발 시각

웨이팅 때문에 일찍 출발해야 하는 식당은 등록·수정 창의 **출발 시각**에 24시간제
`HH:mm`을 입력한다. 예를 들어 `/lunch edit 제주고사리칼국수 시콜`로 기존 정보를
채워 연 뒤 `11:15`를 저장하면 된다. 식당 이름은 `/lunch list`에서 확인한다.
시간을 비워 저장하면 지정이 해제되며, 잘못된 시간은 입력 칸에 오류가 표시되고 저장되지 않는다.

지정한 시각은 식당 목록·검색 드롭다운·투표 메시지·결과에 표시된다. 마감 결과를 기다리면
이미 출발 시각을 놓칠 수 있으므로 **11시 투표가 열릴 때부터** 안내한다.
시각은 `Lunch:TimeZone` 기준이며, 미지정 식당에는 출발 시각을 임의로 붙이지 않는다.
기존 투표 개시·마감 시각과 추천 계산은 바뀌지 않고, 별도 출발 알림도 보내지 않는다.

## 수동 구성원 동기화와 Outlook 메일 검색

PowerShell 7(`pwsh`)로 실행하는 별도 도구다. 점심 봇의 스케줄·투표·알림 동작은 바꾸지 않는다.

- [Slack 구성원 동기화](tools/sync-members/README.md): 설정된 채널의 사람 명단을 로컬 DB에 저장한다.
  워크스페이스·채널·사용자 ID로 구분하며 이름은 검색 키워드로만 사용한다.
- [Outlook 메일 검색](tools/mail-search/README.md): Chromium + Playwright로 Outlook 웹 화면을 검색한다.
  Windows·Linux에서 같은 `pwsh` 진입점을 사용한다. AI·Graph 인증·Windows UI Automation은 사용하지 않는다.
  기본 계정은 `vincent@snuailab.ai`이며 다른 회사에서는 `-Account`로 지정한다.

```powershell
# 최초 로그인·세션 만료 시: 열린 전용 Chromium에서 사용자가 직접 로그인
pwsh -NoProfile -File tools/mail-search/Search-OutlookMail.ps1 -Login
 
pwsh -NoProfile -File tools/mail-search/Search-OutlookMail.ps1 -Name 홍길동 -ReceivedAfter 2026-10-01
pwsh -NoProfile -File tools/mail-search/Search-OutlookMail.ps1 -Account user@company.example -Query 연차,휴가,반차
```

**휴가 정보와 메일 검색 결과·본문은 DB·파일·로그에 저장하지 않는다.** 검색 결과는 메모리와 터미널 출력으로만 제공한다.
터미널 기록·리다이렉션·CI 로그는 별도로 내용을 보관할 수 있으므로 민감한 출력을 저장하지 말 것.
검색 결과는 메일 후보이며 휴가 승인·취소를 자동 판정하지 않는다. Slack 명단 저장에는 메일 검색 결과가 들어가지 않는다.
브라우저는 자동 실행되며, 로그아웃·추가 인증·계정 불일치 상태에서는 검색하지 않는다.
도구 전용 브라우저 프로필에는 로그인 상태와 브라우저 캐시가 남을 수 있다. 계정별 프로필은 저장소 밖에 두고
인증정보로 보호한다. 검색은 항상 창 없이(headless) 실행하며, 같은 운영체제 사용자·프로필에서 수동 로그인을 마친 뒤 사용한다.
메일 도구를 systemd/journald·CI 로그에 직접 연결하면 민감한 stdout이 보관되므로 그렇게 실행하지 않는다.

## 구조

    src/SelectLunch.Shared    추천 알고리즘·스케줄 판정·DB (플랫폼 의존성 0)
    src/SelectLunch.Slack     SlackNet Socket Mode Worker

`Shared`는 Slack을 모른다. Teams head를 나중에 붙일 수 있게 한 경계다.

## 알아둘 점

- **한 번에 하나만 띄운다.** 같은 PC에서의 중복 기동은 뮤텍스로 막히지만, 다른 PC에서
  같은 채널에 붙이면 막을 방법이 없어 메시지가 두 번 나간다.
- **토큰과 채널 ID는 핫리로드되지 않는다.** `appsettings.Local.json`의 `Slack:*` 값을
  바꾸면 재기동해야 한다. 반면 `Lunch:*`(시각·가중치·공휴일 등)는 파일을 저장하는
  즉시 반영된다.
- **법정 공휴일은 계산한다.** `KoreanHolidays`가 양력 고정 공휴일·음력 공휴일(설날·추석·
  부처님오신날)·대체공휴일을 코드로 구해 영업일에서 뺀다(외부 API 없음, 2024~2050년).
  끄려면 `Lunch:UseKoreanHolidays`를 `false`로. `Lunch:Holidays`에는 **계산할 수 없는 날**
  — 임시공휴일, 공직선거법상 선거일(예: 2026-06-03 지방선거) — 만 적는다. 둘은 합집합이다.
- Slack과의 연결이 끊기거나 재연결에 실패하면 앱 로그(`SlackNet.*` 카테고리)에
  남는다 — 프로세스는 살아있어도 아무 메시지가 안 나가는 상태를 로그로 구분할 수 있다.
