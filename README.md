# Select-Lunch

점심 고르자. 슬랙 채널에서 점심 투표를 열고, 알고리즘으로 식당을 추천하는 봇.

개발·빌드에는 .NET 11 SDK가 필요하다. 모든 프로젝트는 `net11.0`을 대상으로 하며 기본 언어 버전인 C# 15를 사용한다.

## 하루 흐름

    10:55  오늘의 메뉴 수집 시작 — 투표 개시 5분 전부터 카카오 채널을 확인한다
    11:00  투표 개시 — 등록된 식당 전체가 후보
    11:25  미참여자 알림 — 아직 투표·기권하지 않은 사람에게 본인만 보이는 메시지 1회
    11:30  마감 → 투표 1위 + 알고리즘 추천 (점수 상세는 개인 창)
    13:30  기록 요청 — 실제로 먹은 곳을 남기면 다음 추천이 정확해진다

시각은 모두 설정으로 바꿀 수 있고, **앱 재기동 없이 반영**된다(단, 토큰·채널 ID는
예외 — [알아둘 점](#알아둘-점) 참고). 메뉴 수집 시작 시각은 따로 설정하지 않고
`Lunch:VoteOpenAt`에서 `Lunch:MenuCollectionLeadMinutes`(기본 5분)를 뺀 값으로
계산되므로, 투표 시각을 옮기면 수집 시각도 함께 따라온다.

오늘의 메뉴 사진이 있으면 투표 메시지 **본문이 아니라 그 메시지의 스레드에 파일로**
올라간다. 본문에 외부 이미지 URL을 실으면 슬랙이 그 URL을 직접 가져오다 실패해
메시지 전체를 거절하는 일이 있어(`invalid_blocks`), 봇이 사진을 직접 내려받아
업로드한다. 사진을 못 구해도 투표는 그대로 진행된다.
업로드 완료 기록은 메뉴 날짜별로 관리한다. 새 날짜의 메뉴를 수집하면 이전 완료 기록을
초기화하므로 다음 날에도 올라가고, 같은 날 성공한 메뉴는 중복 게시하지 않는다.

투표 마감 5분 전부터, 아직 투표하거나 기권하지 않은 채널 구성원에게 **본인만 보이는
비공개 메시지**로 투표를 독려한다. 투표 메시지로 이동하는 링크를 포함하며 봇·비활성
계정은 제외한다. 전송 전에 DB에 시도 기록을 남겨 **투표마다 최대 한 번만** 시도하고,
전송 오류나 재시작 뒤에도 다시 보내지 않는다. 마감 시각부터는 보내지 않는다.

투표 메시지에는 후보 버튼과 함께
**"나 오늘 따로 먹어요"** 버튼이 있다. 이건 투표가 아니라 기권 표시로, 집계·동점
해소·추천 점수·식사 기록 어디에도 영향을 주지 않는다 — 누가 따로 먹는지 채널에
보이게 하는 것이 유일한 목적이다. 집계 아래에 `따로 먹어요 (N) — @이름 @이름` 형태로
명단이 뜬다.

### 회차별 익명 사전투표

투표 채널에서 `/lunchpre`를 입력하면 본인 전용 선택 화면이 열린다. **실제 선택을 바꾸면
누군가 어느 식당에 사전투표했는지와 식당별 득표를 일반 채널 메시지로 공개**한다.
공개 메시지에는 사용자 이름·ID·멘션·개인별 버튼을 넣지 않는다. 집계는 해당 변경 직후의
스냅샷이며, 네트워크 사정에 따라 메시지 도착 순서가 달라질 수 있다.

`/lunchpre`를 열면 **해당 회차의 현재 식당별 득표수와 기권 수**도 본인에게만 표시한다.
조회는 표·사용 횟수를 바꾸거나 공개 알림을 보내지 않는다. 한도를 모두 썼거나 본투표가
진행 중이어도 집계를 볼 수 있다. 열린 메시지는 자동 갱신되지 않으므로 최신 결과는 명령을
다시 입력해 확인한다. 취소·무효 표와 비활성 식당은 집계에서 제외한다.

- **최초 선택 포함 사용자·채널·대상 점심 회차당 총 3회**다. 다른 식당 선택·기권·실제 취소도
  각각 1회이며, 같은 선택 재클릭이나 이미 취소한 선택의 재취소는 차감·게시하지 않는다.
  개인 화면에 사용 횟수를 표시하고, 3회를 모두 쓰면 조회만 가능하다. 랜덤은 제공하지 않는다.
- 오전에는 오늘 점심을 대상으로 한다. **본투표 시작부터 점심 확정까지는 사전투표 조회만**
  가능하며, 본투표가 실제 마감되어 `Closed`가 된 뒤 다음 영업일 회차와 새 한도로 넘어간다.
  주말·공휴일은 건너뛰고, 투표 자체가 생성되지 않은 채 예정 마감 시각을 놓친 날도 건너뛴다.
- 예를 들어 1월 2일 점심 확정 뒤 1월 3일 사전투표를 한 번 했다면, **1월 3일 자정에도 1/3**이다.
  날짜가 바뀌거나 재시작해도 한도를 초기화하지 않는다.
- **유효한 사전표·기권은 본투표가 열릴 때 초기표로 한 번 자동 반영**한다. 첫 게시부터 득표가
  보이며, 재게시·재시작은 다시 복사하지 않는다. 취소·무효 표와 개시 후보에 없는 식당은 제외한다.
  이전 버전에서 저장한 변경 횟수 0의 사전표도 유효하다.
- **본투표에서 실제 선택을 바꾸면 그 회차의 사전표는 무효화**한다. 일반 선택·기권·랜덤·비밀
  투표 모두 적용하며, 본투표 저장과 무효화를 같은 트랜잭션으로 처리한다. 같은 공개 선택을 다시
  누르면 유지하고, 다른 선택을 거쳐 원래 식당으로 돌아와도 사전표가 부활하지 않는다.
  사전 선택 기록·시각·횟수는 남기며 본투표 변경으로 사전투표 3회 한도를 차감·환급하지 않는다.
- 사전 기권은 본투표에서도 **익명 인원수로만** 표시한다. 다른 본투표 선택으로 바꾼 뒤 직접
  기권하면 기존 본투표처럼 이름이 표시된다. 이미 생성된 투표나 마감 결과를 소급 수정하지 않는다.
- 취소는 선택만 없애고 DB 행과 횟수는 남긴다. 기대 변경 횟수와 한도를 조건으로 한 UPDATE가
  카운터 증분·선택 변경을 한 트랜잭션에서 처리한다. 오래된 화면의 변경은 거절하고 최신 화면을
  보여준다. 식당별 득표는 별도의 메모리 카운터가 아니라 취소·무효화되지 않은 DB 표의 COUNT로 계산한다.
- 비활성화된 식당은 사전집계에서 제외한다. 사전 접수 시 휴가 조회·미참여자 알림·미리 출발
  안내를 실행하지 않는다. 초기 반영 후에는 일반 본투표 집계에 포함된다. 기존 비공개 사전표는
  보존하고 실제 사전 선택 변경부터 횟수를 센다.
- 공개 전송은 저장 후 한 번만 시도한다. 전송 실패는 개인 응답으로 알리되 재전송·횟수 환급은
  하지 않는다. 응답 유실이나 저장 직후 재시작으로 공개 안내가 누락될 수 있으나 표·횟수는 유지된다.

### 미리 출발 안내

`/lunchadd`·`/lunchedit`의 **미리 출발(분)**에 시간을 입력한다. 예를 들어 `10`은 DB의
`Restaurant.EarlyDepartureSeconds`에 `600`으로 저장하고, 목록·수정 창·비공개 안내에는
다시 분으로 표시한다. 소수 분도 입력할 수 있으며 가장 가까운 초로 반올림한다.
비우거나 `0`을 입력하면 이 식당의 미리 출발 안내를 끈다.
기존 **출발 시각**은 최종 권장 시각 그대로 표시하며 여기서 추가로 시간을 빼지 않는다.

- 전체 인원 기준은 `Lunch:EarlyDepartureParticipantCount`(기본 **6명**)이다.
  같은 식당의 **공개 투표가 전체 인원의 30% 이상**, 즉 현재 **2명 이상**이면
  그 식당을 선택한 사람들에게만 **나에게만 표시** 메시지로 미리 출발을 안내한다.
  현재 투표 수를 분모로 쓰거나 채널의 봇·휴가 정보를 인원 기준에 반영하지 않는다.
- 일반·일반 랜덤·카테고리 랜덤 투표 직후에 판정한다. 스케줄러도 현재 상태를 다시 확인한다.
  여러 식당이 각각 기준을 만족하면 각 식당의 투표자에게만 안내한다.
  기권·미참여자·비밀 투표는 집계와 수신 대상에서 제외한다.
- 날짜·사용자·식당별 알림 시도를 **서버 메모리에만** 기록한다.
  A에서 B로 바꾸면 B의 조건을 확인하지만, 이미 안내한 A로 돌아오면 다시 보내지 않는다.
  늦게 같은 식당을 고른 사람은 본인 안내가 없으면 받는다.
- 실제 다녀온 식당을 기록하면 그날 기록을 비우고 당일 추가 안내를 종료한다.
  기록 없이 날짜가 넘어가도 새날 기준으로 초기화한다. 서버 재시작은 메모리를 지우므로
  식사 기록 전에는 같은 안내가 다시 갈 수 있다.
- 안내는 현재 투표 기준이며 투표 마감·결과·추천·식사 기록을 자동으로 변경하지 않는다.
  `/lunchtest`는 실제 안내를 발송하거나 중복 방지 기록을 남기지 않는다.
  캐치테이블 연동은 포함하지 않는다.

비공개 메시지는 Slack이 수락해도 사용자 접속 상태에 따라 보이지 않을 수 있다.
중복 방지를 위해 발송 오류는 재시도하지 않는다. [알려진 제약](docs/known-limitations.md)을 참고한다.

### 결과 점수 상세

마감 결과 본문에는 투표 1위·앱 추천·득표·출발 시각과 기존 집계만 표시한다.
긴 점수 계산과 경쟁 항목의 내역은 **점수 자세히 보기** 버튼으로 분리한다.
버튼을 누르면 **누른 사람에게만 읽기 전용 상세 창**이 열리며, 다른 사람의 채널 메시지는 펼쳐지거나 바뀌지 않는다.
내역이 아주 길면 같은 창의 이전/다음 버튼으로 나눠 본다. 조회·쪽 이동은 투표·식사 기록·추천 결과를 바꾸지 않는다.

새 마감은 기존 `RationaleJson`의 추천 데이터에 당시의 상세 문구(`DetailsText`)도 함께 저장한다.
따라서 앱 재시작·가중치 변경·식사 기록 추가 뒤에도 마감 당시의 점수 내역을 읽는다.
상세 문구가 없는 과거 스냅샷은 저장된 점수로만 합산 차감을 표시하며, 당시 가중치를 추정하지 않는다.
점수 데이터가 없거나 손상됐으면 새로 추천하지 않고 해당 사실을 개인 창에서 안내한다.
추가 Slack 권한이나 구형 첨부 메시지는 사용하지 않는다.

### 랜덤 투표와 비밀 투표

식당을 직접 고르는 UI 아래에 **🎲 랜덤으로 고르기** 섹션이 있다. 일반 랜덤·카테고리 랜덤·
비밀 랜덤을 한곳에 모으고, **나 오늘 따로 먹어요**는 별도 구역으로 분리한다.

- **🎲 랜덤 투표**: 현재 후보 중 한 곳에 즉시 투표하고 선택된 식당을 본인에게만 알린다.
- **카테고리 랜덤**: 카테고리 드롭다운을 고르면 해당 카테고리 후보 안에서 랜덤으로 투표한다.
  카테고리가 하나뿐이면 일반 랜덤과 같아 드롭다운은 생략한다.
- **🤫 비밀 투표**: 현재 후보 중 한 곳을 즉시 랜덤 선택해 저장한다. 접수 안내는 본인에게만
  보내며 식당은 숨긴다. 안내의 **👀 내가 뽑은 식당 보기**를 누르면 저장된 식당을 본인에게만
  공개한다. 확인 버튼을 누르지 않으면 본인도 모르는 상태로 남는다.
  - 확인 버튼은 **재추첨·표 추가·공개 집계 변경을 하지 않는다**. 반복 확인해도 같은 식당이다.
  - 마감 전 득표 목록에는 `비밀이에요 — N표`로 합쳐 표시한다.
    마감 시 실제 식당별 득표에 합산한 뒤 최종 승자를 결정한다.
  - 다른 선택이나 새 비밀 투표로 표를 바꾸면 이전 접수 안내의 확인 버튼은 사용할 수 없다.
- 모든 선택은 **1인 1표**다. 비밀 투표 버튼을 다시 누르면 재추첨하며 표 수는 늘지 않는다.
  일반 투표·랜덤 투표·기권으로 바꾸면 이전 비밀 표를 대체한다.
- 선택은 DB에 저장되므로 재시작해도 유지되고, 마감 결과 재발표 때 재추첨하지 않는다.
- `/lunchtest`에서도 비밀 투표 접수와 본인 확인을 체험할 수 있다. 확인은 접수 때 미리 뽑은
  식당을 그대로 보여준다. **실제 표는 저장하지 않으며 테스트 메시지 본문의 집계도 갱신하지 않는다.**


후보가 10곳을 넘으면 버튼 대신 드롭다운으로 바뀐다. 이 드롭다운은 **식당 이름뿐 아니라
카테고리(음식 종류)와 주소에도 부분 일치**로 검색된다 — `순대국`만 쳐도
`옛날경성순대국 광교중앙역점`이 나온다. 슬랙 기본 드롭다운은 클라이언트가 단어 앞부분만
맞춰서 `옛날`부터 쳐야 했는데, 검색을 봇이 직접 처리하도록 바꾼 결과다(식사 기록
드롭다운도 같다). 몇 곳이 등록돼 있든 드롭다운이 뜨며, 한 번에 보여주는 건 상위 100곳이다.

### 실제로 먹은 식당 확정

개인 투표는 한 곳만 고른다. 투표 마감 메시지는 득표와 추천만 알리고, **‘뭐 드셨어요?’**에서
실제로 간 식당을 확정한다. 버튼이나 검색에서 식당을 고르면 개인 창이 열린다. 한 곳만 남기거나
다른 식당을 추가한 뒤 저장한다. 창을 닫거나 검색만 하면 식사 기록이 생기지 않는다.

지정한 점심 채널에서 누구나 **`/lunchsize`**로 식당 한 곳당 기준 인원을 확인하고 **`/lunchsize 4`**로
4명으로 변경할 수 있다. 응답은 입력한 사람에게만 보인다. 채널 설정은 재시작 후에도 유지된다.
**`/lunchsize 기본값`**은 채널 설정을 지우고 `Lunch:MealParticipantsPerRestaurant`(기본 5명)를 다시 따른다.
설정 명령은 투표나 식사 기록을 바꾸지 않는다. 이미 연 확정 창도 저장 시점의 기준을 적용한다.

마감된 식당표 수를 기준 인원으로 나누어 올림한 값이 **최대치**다. 기준 5명이면 1~5명은 한 곳,
6~10명은 최대 두 곳, 11~15명은 최대 세 곳이다. 기권·미응답은 제외하고 비밀표와 본투표에
반영한 사전표도 각 1명으로 센다. 식당표나 마감된 투표가 없는 날도 한 곳은 기록할 수 있다.

당일에는 다시 열어 방문 목록 전체를 정정할 수 있다. 등록되지 않은 곳은 **새 식당 등록**으로
기록하며 함께 방문한 기존 식당도 추가할 수 있다. 식당별로 해당 날짜의 방문 1회씩 추천에 반영한다.
과거·미래 요청은 잠긴다. 예외는 운영자가 지정한 **게시됐지만 미기록인 과거 요청 하나의 최초 저장**뿐이다.
이미 확정한 과거 식사는 덮어쓰지 않는다. [운영 예외 설정](docs/deployment.md#이미-게시된-식사-기록-요청) 참고.

카테고리 정보가 비어 추천에서 빠진("Pending") 식당이 있으면 매주 금요일
`Lunch:PendingReminder:At`(기본 16:00)에 보완 요청 메시지가 따로 올라온다.

## 추천 알고리즘

랜덤을 쓰지 않는다. 카테고리별로 점수를 매겨 결정적으로 고른다.

    score = D − (W7 × N7 + W30 × N30)

      D   = 마지막으로 먹은 날로부터 경과일 (상한 30, 미방문도 30)
      N7  = 최근 7일 식사 횟수     (기본 가중치 3)
      N30 = 최근 30일 식사 횟수    (기본 가중치 1)

점수가 가장 높은 카테고리에서, 마지막 방문이 가장 오래된 식당을 고른다.
결과만이 아니라 **계산 과정 전체를 메시지에 노출**한다. 기권은 이 계산에 전혀
관여하지 않는다 — 투표하지 않은 것과 동일하게 취급된다.

## 시작하기

1. [Slack 앱 설정](docs/slack-app-setup.md)을 따라 토큰을 발급한다
2. `src/SelectLunch.Slack/appsettings.Local.example.json`을
   `appsettings.Local.json`으로 복사하고 토큰·채널 ID를 채운다
3. 실행한다

```bash
dotnet run --project src/SelectLunch.Slack
```

DB(`data/lunch.db`)는 기동 시 자동 생성·마이그레이션된다. 별도 준비가 필요 없다.
토큰이 비어 있거나 형식이 틀리면(예: `xoxb-`로 시작하지 않음), 또는 `Lunch:TimeZone`이
잘못된 타임존 ID면 스택 트레이스 없이 한 줄 메시지와 함께 즉시 종료한다(종료 코드 1).

## 명령어

`/lunch`는 도움말 전용입니다. 기존 서브커맨드 실행은 지원하지 않습니다.

| 명령 | 동작 |
|---|---|
| `/lunch` | 점심 봇 명령어와 사용법을 확인합니다. |
| `/lunchadd [이름]` | 새 식당을 등록합니다. 이름을 넣으면 등록 창에 미리 채웁니다. |
| `/lunchedit [이름]` | 등록된 식당을 선택해 수정합니다. 이름을 넣으면 바로 엽니다. |
| `/lunchlist` | 등록된 식당을 카테고리별로 확인합니다. |
| `/lunchpending` | 카테고리가 없어 추천에서 제외된 식당을 확인합니다. |
| `/lunchstats` | 카테고리별 추천 점수와 최근 식사 횟수를 확인합니다. |
| `/lunchtoday` | 오늘 투표의 진행·마감 상태를 확인합니다. |
| `/lunchpre` | 다음 점심에 사전투표합니다. 선택은 익명 공개되며 회차당 3회까지 가능합니다. |
| `/lunchsize [인원 또는 기본값]` | 식당 한 곳당 기준 인원을 조회·변경하거나 서버 기본값으로 되돌립니다. |
| `/lunchtest` | 실제 표를 저장하지 않고 투표 화면을 나에게만 미리 봅니다. |

기존 식당을 수정할 때는 `/lunchedit`만 입력하면 된다. **수정할 식당 선택** 창의 목록을
열면 상호가 카테고리별로 나오고, 상호 일부·음식 종류·주소를 입력해 검색할 수 있다.
선택하면 같은 창이 **식당 수정**으로 바뀌며 미리 출발 시간을 포함한 기존 값이 채워진다.
분류가 미완성인 식당도 선택할 수 있고 보관된 식당은 제외한다.
선택·취소만으로는 저장하지 않으며, 수정 창에서 **저장**해야 기존 식당이 변경된다.
등록된 식당이 없으면 신규 등록 안내만 표시한다. `/lunchadd`는 신규 등록용 빈 창을 유지한다.


## 식당별 출발 시각

웨이팅 때문에 일찍 출발해야 하는 식당은 등록·수정 창의 **출발 시각**에 24시간제
`HH:mm`을 입력한다. 예를 들어 `/lunchedit 제주고사리칼국수 시콜`로 기존 정보를
채워 연 뒤 `11:15`를 저장하면 된다. 식당 이름은 `/lunchlist`에서 확인한다.
시간을 비워 저장하면 지정이 해제되며, 잘못된 시간은 입력 칸에 오류가 표시되고 저장되지 않는다.

지정한 시각은 식당 목록·검색 드롭다운·투표 메시지·결과에 표시된다. 마감 결과를 기다리면
이미 출발 시각을 놓칠 수 있으므로 **11시 투표가 열릴 때부터** 안내한다.
시각은 `Lunch:TimeZone` 기준이며, 미지정 식당에는 출발 시각을 임의로 붙이지 않는다.
기존 투표 개시·마감 시각과 추천 계산은 바뀌지 않고, 별도 출발 알림도 보내지 않는다.

## 메뉴의 휴가자 표시

`LeaveDisplay:Enabled`를 켜면 메뉴 게시 전에 채널의 사람 명단을 DB에 동기화하고 Outlook 메일을 조회한다.
이 회사(`snuailab`)는 메일 제목의 **휴가·연차·오전 반차를 승인된 것으로 간주**한다.
실제 메일은 일정 초대 형식이며, 수신일이 아닌 **본문의 일정 기간**이 메뉴 날짜를 포함할 때 표시한다.
캘린더를 별도로 조회하거나 변경하지 않는다.

- 메일에서 추출한 이름을 현재 워크스페이스·채널의 활성 구성원 실명·별칭과 대조한다.
  NFC·공백 정리 후 정확 일치를 먼저 보고, 없으면 양방향 접미사 관계를 검사한다.
  서로 다른 사람이 여러 명 맞으면 임의로 선택하지 않는다.
- 메뉴에 `오늘 휴가: 별칭, 별칭`을 **일반 텍스트로 표시하며 멘션하지 않는다.**
  별칭이 없으면 실명을 쓴다. 투표·집계·기권·미참여자 알림 제외 정책은 바꾸지 않는다.
- 같은 투표의 조회 결과는 RAM에만 두고 메뉴 갱신·마감 때 재사용한다.
  앱 재시작이나 새 투표에서는 다시 조회한다. `/lunchtest`는 같은 채널의 완료된 캐시만 사용해 브라우저를 기다리지 않는다.
- 일부 메일·이름·기간만 확정하지 못했을 때(해석하지 못한 휴가 양식 메일, 메뉴일 기간을 확정하지 못한 채널 구성원,
  서로 다른 두 사람에게 맞는 이름, 표시할 별칭이 없는 사람) **이미 확인된 휴가자는 숨기지 않는다.**
  확인된 사람은 위처럼 표시하고 명단 바로 뒤에 `휴가 정보: 일부는 확인하지 못해 명단이 완전하지 않을 수 있습니다`
  경고를 한 번만 덧붙인다. 이 명단은 “전부”가 아니다. 로그에는 처음 만난 원인 분류만 남는다.
- 조회 실패·로그아웃·잘린 검색·시간 초과·채널 명단 수집 실패는 “휴가자 없음”이 아니라
  `휴가 정보: 확인하지 못했습니다`로 표시한다. 위 일부 미확정 항목만 있고 확인된 휴가자가 **한 명도 없을 때도** 같다.
  메뉴 자체는 계속 제공한다.
- **메일·휴가 기간·휴가자 명단은 DB·파일·로그에 저장하지 않는다.**
  DB에는 기존 채널 구성원 명단만 저장한다. 사용자가 요청한 Slack 메뉴의 별칭 표시는 이 비저장 원칙의 예외다.
  본문을 여는 검색이므로 Outlook의 읽음 표시는 바뀔 수 있다.

기본값은 비활성이다. Linux 실행기를 준비하고 같은 서비스 사용자로 수동 로그인한 뒤,
`appsettings.Local.json`에 다음을 추가하고 앱을 재시작한다.

```json
"LeaveDisplay": {
  "Enabled": true,
  "Provider": "snuailab",
  "Executable": "/home/autocare/.local/share/SelectLunch/mail-search-runtime/bin/search-outlook-mail",
  "Account": "vincent@snuailab.ai",
  "TimeoutSeconds": 90,
  "MaxResults": 1000
}
```

Windows에서는 `Executable`에 실제 `pwsh.exe` 경로를, `Arguments`에
`["-NoProfile", "-File", "Search-OutlookMail.ps1의 절대 경로"]`를 지정한다.
공통 검색·명단 동기화·이름 대조와 회사별 `ILeaveMailParser`는 분리되어 있다.
다른 회사의 메일 검색은 계정만 바꾸면 되지만, 휴가 메일 양식이 다르면 회사 파서와 제공자 등록을 추가해야 한다.
자세한 운영 준비는 [배포 문서](docs/deployment.md)를 따른다.


## 수동 구성원 동기화와 Outlook 메일 검색

PowerShell 7(`pwsh`)로도 독립 실행할 수 있다. 봇 연동은 위 `LeaveDisplay`를 명시적으로 켠 경우에만 동작한다.

- [Slack 구성원 동기화](tools/sync-members/README.md): 설정된 채널의 사람 명단을 로컬 DB에 저장한다.
  워크스페이스·채널·사용자 ID로 구분하며 이름은 메일 대조와 별칭 표시에 사용한다.
- [Outlook 메일 검색](tools/mail-search/README.md): Playwright로 도구용 Chromium 또는 설치된 Google Chrome의 Outlook 웹 화면을 검색한다.
  Windows·Linux에서 같은 `pwsh` 진입점을 사용한다. AI·Graph 인증·Windows UI Automation은 사용하지 않는다.
  기본 계정은 `vincent@snuailab.ai`이며 다른 회사에서는 `-Account`로 지정한다.
  `-BrowserChannel chrome`으로 시스템 Chrome을 선택한다. 기본 Chromium과 로그인 프로필은 유지되며, Chrome은 별도 전용 프로필을 쓴다.

```powershell
# 최초 로그인·세션 만료 시: 선택한 브라우저의 전용 창에서 사용자가 직접 로그인
pwsh -NoProfile -File tools/mail-search/Search-OutlookMail.ps1 -Login
 
pwsh -NoProfile -File tools/mail-search/Search-OutlookMail.ps1 -Name 홍길동 -ReceivedAfter 2026-10-01
pwsh -NoProfile -File tools/mail-search/Search-OutlookMail.ps1 -Account user@company.example -Query 연차,휴가,반차
```

**휴가 정보와 메일 검색 결과·본문은 DB·파일·로그에 저장하지 않는다.** 검색 결과는 메모리와 터미널 출력으로만 제공한다.
터미널 기록·리다이렉션·CI 로그는 별도로 내용을 보관할 수 있으므로 민감한 출력을 저장하지 말 것.
독립 검색 도구는 후보만 반환한다. 승인 간주·휴가일 판정은 봇의 회사별 파서가 담당하며, Slack 명단 저장에는 메일 결과가 들어가지 않는다.
브라우저는 자동 실행되며, 로그아웃·추가 인증·계정 불일치 상태에서는 검색하지 않는다.
도구 전용 브라우저 프로필에는 로그인 상태와 브라우저 캐시가 남을 수 있다. 계정·브라우저별 프로필은 저장소 밖에 두고
인증정보로 보호한다. 검색은 항상 창 없이(headless) 실행하며, 같은 운영체제 사용자·프로필에서 수동 로그인을 마친 뒤 사용한다.
메일 도구 stdout을 systemd/journald·CI 로그에 직접 연결하지 않는다. 봇 연동은 자식 프로세스의 JSON을 RAM으로만 받고 원문을 기록하지 않는다.

    src/SelectLunch.Shared    추천 알고리즘·스케줄 판정·DB (플랫폼 의존성 0)
    src/SelectLunch.Slack     SlackNet Socket Mode Worker

## 알아둘 점

- **한 번에 하나만 띄운다.** 같은 PC에서의 중복 기동은 뮤텍스로 막히지만, 다른 PC에서
  같은 채널에 붙이면 막을 방법이 없어 메시지가 두 번 나간다.
- **토큰과 채널 ID는 핫리로드되지 않는다.** `appsettings.Local.json`의 `Slack:*` 값을
  바꾸면 재기동해야 한다. 반면 `Lunch:*`(시각·가중치·공휴일 등)는 파일을 저장하는
  즉시 반영된다.
- **법정 공휴일은 계산한다.** `KoreanHolidays`가 양력 고정 공휴일·음력 공휴일(설날·추석·
  부처님오신날)·대체공휴일을 코드로 구해 영업일에서 뺀다(외부 API 없음, 2024~2050년).
  끄려면 `Lunch:UseKoreanHolidays`를 `false`로. `Lunch:Holidays`에는 **계산할 수 없는 날**
  — 임시공휴일, 공직선거법상 선거일(예: 2026-06-03 지방선거) — 만 적는다. 둘은 합집합이다.
- Slack과의 연결이 끊기거나 재연결에 실패하면 앱 로그(`SlackNet.*` 카테고리)에
  남는다 — 프로세스는 살아있어도 아무 메시지가 안 나가는 상태를 로그로 구분할 수 있다.

### 테스트 배치

테스트 파일은 프로젝트 루트에 나열하지 않고 대상의 책임별 폴더에 둔다.

- `tests/SelectLunch.Shared.Tests`: `Data`, `Leave`, `Members`, `Options`,
  `Recommendation`, `Scheduling`, `Search`, `Tools/SyncMembers`, `Infrastructure`.
- `tests/SelectLunch.Slack.Tests`: `Blocks`, `Handlers`, `Services`, `Leave`,
  `Options`, `Workers`, `Infrastructure`. 회사별 휴가 파서는 `Leave/Snuailab`에 둔다.
- 공용 DB·시계·Slack 대역·임시 디렉터리 도우미는 각 프로젝트의 `TestSupport`에 둔다.
  Slack 테스트가 공유하는 `TestDb.cs`는 Shared 테스트의 `TestSupport/TestDb.cs`를 링크한다.

테스트 네임스페이스는 기존 프로젝트 루트 기준을 유지한다. 폴더 이동으로 테스트 이름이나
이름 기반 필터가 바뀌지 않으며, 새 테스트도 해당 책임 폴더에 추가한다.
